# Open questions — the Bend 2 port of Toon

<!-- A spec gap is never resolved by reading the original's source during
     implementation; it is resolved by RUNNING the original on a new case,
     capturing it as a golden, and amending the spec clause. Each entry
     names the case that resolved it. -->

| id | question | spec clause | resolve by (case to add) | resolution | date |
|---|---|---|---|---|---|
| OQ-001 | What text does the original print for a JSON float: when does it switch to exponent form, and how is the exponent written? | S7 | `decfmt_exp_upper_boundary`, `decfmt_exp_lower_boundary`, `decfmt_exp_shapes`, `decfmt_exp_compact_and_expand` | RESOLVED by capture: shortest round-trip digits; with `e` the decimal exponent of the first digit, plain decimal when −5 ≤ e ≤ 15 (an integer value gets `.0`: `100.0`, `1234567890123456.0`), otherwise `d[.ddd]e±X` with an explicit `+`, no zero padding (`1e+16`, `9.9e-6`, `1.2345678901234568e+16`). Same text from both JSON writers. | 2026-09-20 |
| OQ-002 | Is JSON number input correctly rounded to binary64? | S7 | `encnum_long_mantissa`, `encnum_u64_boundary`, `encnum_frac_long`, `encnum_pow10_slow_path`, `encnum_pow10_each`, `encnum_mixed_digits` | RESOLVED by capture: no. `0.3333333333333333333333` encodes as `0.33333333333333337` and `1.00000000000000011102230246251565` as `1.0000000000000002`, while the same tokens on the decode side give `0.3333333333333333`-class correct results (`decnum_long_mantissa` n07 = `1.0`). The encode side is serde_json 1.0.151's default float path; the spec numbers its steps from `serde_json-1.0.151/src/de.rs` and the port reproduces them in software binary64. | 2026-09-20 |
| OQ-003 | How is the `--stats` percentage rounded when the exact ratio sits on a half? | S7 | `stats_ratio_1` … `stats_ratio_5`, `stats_small`, `stats_users` (add a crafted tie case once the token estimator is specified) | OPEN: capture a case whose exact percentage ends in 5 at the second decimal, then record RESOLVED with the verbatim line and the amended clause | |
| OQ-004 | Can the compiled Bend binary receive `--help`, `--version`, `--threads`-like words as program arguments? | S8 | every case is run by the harness as `<port> -- <argv>` | RESOLVED by the runtime facts (RUNTIME-FACTS-FOR-PORTERS, argv): the runtime consumes `--help`, `--threads N`, `--gpu X` before `--` and passes everything after `--` through. Goldens hold behind `--`; the bare spelling is DISC-001 (Platform). | 2026-09-20 |
| OQ-005 | Which of clap's unexpected-argument outputs are a fixed pattern and which need clap's similarity engine? | S9 | `usage_unknown_flag`, `usage_unknown_short`, `usage_extra_positional` captured; a near-miss flag (`--encod`) prints `tip: a similar argument exists: '--encode'` and `Usage: toon --encode [INPUT]` | RESOLVED for scope: the fixed patterns are in scope and captured; the similarity tip is excluded in PLAN §3 (external-dependency, debt) and has no case. | 2026-09-20 |
| OQ-006 | Does the original prefix decode failures with `Failed to decode TOON:` as its README says? | S9 | every `toonerr_*` and `fx_dec_*` error case | RESOLVED by capture: no prefix. JSON input errors print `JSON error: Failed to parse JSON: <serde_json message> at line L column C`. | 2026-09-20 |
| OQ-007 | Does decoding print integers as integers, as the README's examples show (`{"id":1,…}`)? | S7 | `happy_readme_users_decode`, `decnum_ints` | RESOLVED by capture: no. Every decoded number is an f64 and prints through the float writer: `1.0`, `42.0`, `1000000.0`. Bug-compatible by default; listed for the owner in DISCREPANCIES as a candidate BugFix (not taken). | 2026-09-20 |
| OQ-008 | What OS error text reaches stderr for a missing file, a directory, an uncreatable output, and is it producible on every Bend lane? | S8, S9 | `usage_missing_file`, `usage_dir_as_input`, `usage_output_bad_dir` | RESOLVED by probe on the interpreter, C and JS lanes (2026-09-20): `File.open` / `File.read_bytes` fail with the pair (errno, strerror text), identical on the three lanes: (2, `No such file or directory`), (21, `Is a directory`; the open succeeds and the first read fails, as in the original), (13, `Permission denied`). The original prints `<strerror> (os error <errno>)`, so the port builds the same text from the pair. No `ErrorText` DISC. | 2026-09-20 |
