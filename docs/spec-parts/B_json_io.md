# Part B — JSON text input and JSON text output (extractor X-B)

Surface: (1) JSON text input as the pinned binary accepts it (`serde_json 1.0.151`, `from_str::<Value>`, feature `preserve_order`
only), (2) the conversion from that parser's value to the tool's own value model, (3) JSON text output by both writers.
Owned clause ranges: S2.1–S2.99, S5.50–S5.99, S6.10–S6.19, S9.50–S9.99, S10.20–S10.39. Extracted 2026-09-20 against
`./oracle/toon` (sha256 `980f2b26…`), commit `f955c67`.

**Provenance shorthand.** `de.rs`, `read.rs`, `value/de.rs`, `map.rs`, `ser.rs`, `number.rs` without a directory are files of
`/home/ubuntu/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/serde_json-1.0.151/src/`; that crate's error file is always written in full as
`serde_json-1.0.151/src/error.rs`. Paths beginning `src/` are under `legacy/Toon/`. `indexmap-2.14.0/src/map.rs` is under the same registry directory.

**Byte notation used in every example of this part.** `⏎` is one LF byte (0x0A), `⇥` one TAB (0x09), `␍` one CR (0x0D), `␀` one NUL (0x00),
`\xNN` (only where stated as a raw byte) the byte NN. Every other character stands for itself: a backslash in an example is one literal backslash byte
of the input, so `"\ud800"` is the eight input bytes quote, backslash, `u`, `d`, `8`, `0`, `0`, quote. `é` is the two bytes C3 A9, `€` the three
bytes E2 82 AC, `😀` the four bytes F0 9F 98 80. `L:C` abbreviates `line L column C`. `len` is the byte length of the whole input.

**Numbers.** Only the *lexical* grammar of numbers, and the place at which a number error is reported, belong to this part. The numeric value of a
token, the text of a number inside TOON or JSON output, and the overflow threshold are X-C's clauses (S7 and its S4/S5 rows); they are referenced, not restated.
