# Part D — the encoder: JSON value → TOON text

Extractor X-D, Phase 1, 2026-09-20. Original: `legacy/Toon` at `f955c67` (`toon 0.2.4`); oracle `./oracle/toon`.
Owned clause ranges: **S3.1–S3.19**, **S4.1–S4.99**, **S5.1–S5.29**, **S6.30–S6.39**, **S10.60–S10.79**.
Owned case prefixes: `fx_enc_` (147), `encstr_` (15), `enc_` (5), `large_` (2): 169 cases, all cited below.

Surface: from an in-memory JSON value (S3) to the exact TOON lines and the bytes the CLI prints for them.
Not in this part: reading JSON text (another part), the decimal text of a non-zero number (another part; here
"the number's text" is given), flag parsing (another part), `--stats` and `-o` reporting (another part).

Provenance paths are relative to `legacy/Toon/`. `Rnn` refers to the numbered oracle runs in the Extractor report.

## Notation used in examples

- `⏎` stands for the line break between two output lines (one U+000A byte in stdout). The final `\n` that the CLI
  writes after the last line (S5.1) is not shown in examples.
- `⇥` stands for one raw TAB (U+0009) in the output. `<U+XXXX>` stands for that single raw code point.
- Inside a table a literal pipe character is written `\|`; it is one `|` byte in the real text.
- Inside code spans every space is literal and counts. Indentation in examples is real.
- In OUTPUT text, a backslash sequence inside double quotes (such as `\n` or `\"`) is two literal characters
  (a backslash and a letter or quote). In JSON INPUT text the same spelling is a JSON escape.
- "depth" is a non-negative integer; a line at depth d starts with `indent × d` spaces (S4.61). Examples use the
  default indent 2 and the default delimiter comma unless flags are shown in square brackets.
