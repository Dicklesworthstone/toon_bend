# Part E — the decoder: TOON text → events → JSON value, plus path expansion

Extractor X-E. Surface: everything between the TOON input text and the event stream / value handed to the
JSON writers (`toon --decode`, with and without `--expand-paths safe`). The JSON writers themselves and the
text of numbers belong to other parts; here a decoded number is "the binary64 value of the token" and example
outputs show numbers the way the goldens print them (`1.0`).

Provenance paths are relative to `legacy/Toon/` (commit `f955c67`). Every behavior below was checked against
`./oracle/toon`; rows marked "probe" quote an oracle run made for this extraction (about 600 runs, listed by
family in the Extractor report).

**Notation used in examples.** `⏎` is one LF byte, `⇥` one TAB byte, `␍` one CR byte, `␠` one U+0020 where the
count matters (indentation, trailing spaces); every other character, backslashes and quotes included, is
literal. `→` separates input from result. Results are written as compact JSON values (the real stdout layout is
the JSON writer's business); `ERR: <message>` means: that message plus one LF on stderr, exit code 1, stdout
empty. "strict" means `--no-strict` absent; "lenient" means `--no-strict` given. `I` is the `--indent` value
(default 2, range 0–16). "WS-trim" means removal of leading and trailing White_Space characters (S2.106).

## S3. Data model — the event stream and the decoded value (S3.20–S3.39)
